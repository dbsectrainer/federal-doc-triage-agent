# FedRAMP / NIST 800-53 Alignment: Federal Document Triage Agent

> **Status: design mapping, not an assessment or authorization.**
>
> This document was previously written as if the repository implemented a full
> FedRAMP Moderate system. That was not accurate. As verified on **2026-11-01**,
> this repository contains a locally tested Python CLI/LangGraph workflow and a
> Terraform infrastructure baseline. It has **no FedRAMP authorization, no 3PAO
> assessment, no ATO, and no independently verified AWS deployment**. Do not use
> this document as evidence of compliance.
>
> The sections below distinguish what is implemented in code from what is a
> deployment/assessment responsibility or a gap. See
> [`docs/evidence/verification-report.md`](docs/evidence/verification-report.md)
> for the audit evidence and [`SECURITY.md`](SECURITY.md) for security caveats.

## 1. What Is Actually Implemented

| Area | Code-level implementation | Verified? |
| --- | --- | --- |
| Audit events | `AuditorAgent`, per-workflow `ContextVar`, DynamoDB persistence attempted in live mode | Yes (unit/integration; no live DynamoDB) |
| Audit failure handling | Persistence failure sets `processing_complete=False` and preserves error | Yes |
| PII protection | Comprehend (live) / regex fallback; span merge; redact before classification | Yes (mocked Comprehend/Textract) |
| Sensitive-document approval | CUI/SBU/FOUO can never auto-approve | Yes |
| Classification safety | Sanitized ID, untrusted-content tags, truncation, validated output | Yes |
| Human-review routing | Queue/reviewer/SLA assignment with type-default fallback | Yes |
| Input validation | Lambda document-ID, encoding, and size checks | Yes (mocked Lambda) |
| State minimization | Lambda writes omit raw/redacted document bodies | Yes |
| Container hardening | Non-root user, `.env` excluded, dependency audit clean | Yes |
| Infrastructure baseline | VPC/flow logs, KMS, encrypted/versioned/Object-Lock S3, DynamoDB, CloudTrail, optional GuardDuty/Security Hub | `terraform validate` only; not applied |
| Encryption settings | Terraform configures KMS for S3/DynamoDB and CloudTrail log validation | Static validation only |

## 2. What Is Not Implemented

These are requirements or future work, not controls that can be claimed:

- Lambda execution role and least-privilege runtime IAM policies.
- Lambda function, API Gateway, S3 event notification, and deployment pipeline.
- SNS/SES reviewer notifications and Step Functions human-in-the-loop.
- Authentication/authorization (Cognito, MFA, PIV/CAC, SSO). None exists.
- Secrets Manager integration. Settings come from environment variables; AWS
  credentials use the standard provider chain.
- WAF, ALB, RDS, EBS, Istio/mTLS, Kubernetes, or VPC endpoints. These are not in
  this repository.
- S3 archival of processed documents and Object Lock object writes.
- CloudTrail query/alerting integration, CloudWatch alarms, incident response
  runbook, SIEM export, vulnerability management program.
- Backup/disaster recovery, contingency planning, configuration baseline,
  personnel security, physical security, and continuous monitoring evidence.
- Live AWS integration tests, load tests, penetration tests, or a 3PAO
  assessment.
- FedRAMP authorization, ATO, or FISMA compliance certification.

| AU-2 | Event logging | `AuditorAgent` emits workflow events | **Implemented (local)** |

| AU-6 | Audit review/analysis/reporting | No reviewer UI, alerting, or analysis workflow | **Gap** |
| AU-9 | Protection of audit information | KMS-encrypted DynamoDB/S3 in Terraform; no Object Lock write path | **Partial (static)** |
| AU-12 | Audit generation | Events generated by every node | **Implemented (local)** |
| CM-2 | Baseline configuration | Terraform and pinned requirements | **Partial** |
| CM-6 | Configuration settings | `.env.example`, Terraform variables | **Partial** |
| CP-9 | System backup | No backup/restore procedure or test | **Gap** |
| IA-2 | User identification/auth | No authentication layer | **Gap** |
| IA-5 | Authenticator management | No credential storage/rotation implementation | **Gap** |
| IR-4 | Incident handling | No incident response runbook | **Gap** |

| SC-8 | Transmission confidentiality | AWS SDK HTTPS; no app TLS endpoint | **Inherited / partial** |

| SI-12 | Information handling/retention | PII redaction and state minimization; no archive/retention job | **Partial** |

This is not a complete Moderate baseline. A real assessment must enumerate every
control, inheritance source, evidence artifact, and gap with an independent
assessor.

## 4. Inheritance and Shared Responsibility

If deployed to AWS GovCloud, some controls could be inherited from the AWS
environment (physical security, hypervisor, managed-service availability).
Those inheritances were **not** reviewed, and no FedRAMP package or customer
responsibility matrix is included here. The application's own responsibilities
(IAM, network, logging, incident response, personnel, contingency planning)
remain largely unimplemented.

## 6. Recommended Path to a Real Authorization

1. Implement the Lambda/API/notification architecture and least-privilege IAM.
2. Deploy to a non-production GovCloud account with CloudTrail, Config, GuardDuty,
   Security Hub, and centralized logging.
3. Add authentication (Cognito/PIV), authorization, and reviewer directory.
4. Implement retention/archive writes and verify Object Lock.
5. Build an incident response plan and test it.
6. Run SAST/DAST/dependency scanning continuously and remediate findings.
7. Engage a FedRAMP-accredited 3PAO and build the authorization package.
8. Maintain continuous monitoring and a POA&M.

Until then, describe this repository as **"NIST 800-53-aligned design and
reference implementation"**, never as "FedRAMP authorized" or "compliant".
